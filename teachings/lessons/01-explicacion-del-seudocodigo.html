Lección 1: Explicación Línea por Línea del Seudocódigo

Esta lección te prepara para defender la primera parte de la presentación usando la Pestaña 1 (Comparativa de Código). Compararemos en paralelo la versión original de la cátedra con nuestra Variante Óptima y con la Variante No Óptima (Literal).

La idea central para la defensa: En el código original de la cátedra, el arreglo Nodo[] U cumplía dos funciones simultáneas: (1) selección del mínimo en $O(V)$ y (2) tabla de acceso directo $O(1)$ para consultar costos y predecesores. La Cola de Prioridad reemplaza únicamente la primera función (bajándola a $O(\log V)$), pero se conserva el arreglo indexado para mantener el acceso $O(1)$.

1. La Estructura Nodo

class Nodo {
    boolean selec  // Indica si el camino más corto hacia este vértice ya es definitivo.
    int costo      // Costo mínimo tentativo acumulado desde el vértice origen 0.
    int prev       // Vértice inmediatamente anterior para reconstruir el camino.
}

Tanto en la cátedra como en nuestra variante óptima, cada vértice tiene asociado este registro en el arreglo U para garantizar lecturas y escrituras en tiempo constante $O(1)$.

3. La Inicialización: crearArreglo

Versión Cátedra (Arreglo U)

Nodo[] crearArreglo(GrafoTDA G) {
  int cant = G.vertices()
  Nodo[] Arreglo = new Nodo[cant]
  for (int i = 0; i < cant; i++) {
    Nodo O = new Nodo()
    O.prev = 0
    if (i == 0) {
      O.selec = true
      O.costo = 0
    } else {
      O.selec = false
      if (G.existeArista(0, i))
        O.costo = G.pesoArista(0, i)
      else
        O.costo = ∞
    }
    Arreglo[i] = O
  }
  return Arreglo
}

Variante Óptima (Limpia)

Nodo[] crearArreglo(GrafoTDA G) {
  int cant = G.vertices()
  Nodo[] Arreglo = new Nodo[cant]
  for (int i = 0; i < cant; i++) {
    Nodo O = new Nodo()
    O.prev = 0
    O.selec = false
    O.costo = (i == 0) ? 0 : ∞
    Arreglo[i] = O
  }
  return Arreglo
}

¿Por qué cambia? La cátedra hacía una pre-inspección manual de las aristas del vértice 0 dentro de la inicialización y lo marcaba como visitado de entrada. En nuestra versión óptima, todos los vértices inician en selec = false, de modo que el nodo 0 es procesado de forma unificada y limpia en la primera vuelta del ciclo while.

4. La Propagación: actualizar

Versión Cátedra Variante Óptima (Cola de Prioridad) 
void actualizar(GrafoTDA G, Nodo[] A, int i) {
  // Recorre TODOS los V vértices
  for (int j = 0; j < A.length; j++) {
    if (!A[j].selec && G.existeArista(i, j)) {
      int nuevo = A[i].costo + G.pesoArista(i, j)
      if (nuevo < A[j].costo) {
        A[j].costo = nuevo
        A[j].prev = i
      }
    }
  }
}
 
void actualizar(GrafoTDA G, Nodo[] A, ColaPrioridadTDA Q, int i) {
  // Recorre SOLO los vecinos salientes reales
  for (int j : G.adyacentes(i)) {
    if (!A[j].selec) {
      int nuevo = A[i].costo + G.pesoArista(i, j)
      if (nuevo < A[j].costo) {
        A[j].costo = nuevo
        A[j].prev = i
        Q.acolarPrioridad(j, nuevo) // <-- Llena la cola
      }
    }
  }
}

5. ¿Qué pasó con completo(U) y buscarMinimo(U)?

¡Ambas funciones desaparecen por completo en la versión óptima!
  • completo(U) recorría las $V$ posiciones en cada vuelta ($O(V)$). Se sustituye por !Q.colaVacia() en $O(1)$.
  • buscarMinimo(U) recorría las $V$ posiciones buscando el menor ($O(V)$). Se sustituye por Q.desacolar() en $O(\log V)$.

6. El Contraste: ¿Qué pasa si eliminamos el arreglo U por completo?

En la tercera columna de la Pestaña 1 mostramos la Variante No Óptima / Literal: 

void actualizarSinArreglo(GrafoTDA G, ColaPrioridadTDA Q, int i, int cI) {
  ColaPrioridadTDA QAux = new ColaPrioridad()
  QAux.inicializarCola()
  while (!Q.colaVacia()) { // Debe vaciar toda la cola para buscar vecinos
    int j = Q.primero(); int cJ = Q.prioridad(); Q.desacolar()
    if (G.existeArista(i, j)) {
      int nuevo = cI + G.pesoArista(i, j)
      if (nuevo < cJ) cJ = nuevo
    }
    QAux.acolarPrioridad(j, cJ)
  }
  while (!QAux.colaVacia()) { // Y volver a pasarla a la cola original
    Q.acolarPrioridad(QAux.primero(), QAux.prioridad()); QAux.desacolar()
  }
}

Esto demuestra por qué una Cola de Prioridad no reemplaza a un arreglo indexado: no permite consultar U[j].costo por índice, obligando a desencolar y reencolar en cada paso, degradando el algoritmo a $O(V^3)$.
